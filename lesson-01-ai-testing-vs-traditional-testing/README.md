
# Lesson 01: AI Testing vs Traditional Software Testing

## Project Objective
Understand the differences between traditional software testing and AI testing through practical experiments using ChatGPT.

## Tools Used
- ChatGPT – AI system under test
- GitHub – Project repository
- Manual test execution and documentation

## Concepts Covered
- Traditional Software Testing
- AI and LLM Testing
- Accuracy Validation
- Response Consistency
- Negative Testing
- Clarity Validation

## Test Scenarios Executed

| Test Case ID | Test Scenario | Expected Result | Status |
|---|---|---|---|
| AI-001 | Basic Response Validation | Simple explanation with three examples | Pass |
| AI-002 | Accuracy Validation | Correct explanation of Selenium | Pass |
| AI-003 | Consistency Validation | Same core meaning in repeated answers | Pass |
| AI-004 | Negative Input Validation | AI corrects a false statement | Pass |
| AI-005 | Clarity Validation | Beginner-friendly API testing explanation | Pass |

## Key Learning

Traditional software testing generally validates predefined rules and expected results.

AI testing also evaluates generated responses for accuracy, relevance, consistency, clarity, and reliability.

## Practical Observations

1. AI provided a simple explanation of software testing.
2. AI correctly identified Selenium as a browser automation tool.
3. Repeated questions produced answers with the same core meaning.
4. AI corrected a deliberately false statement.
5. AI explained API testing using understandable language.

## Execution Summary

- Total test cases: 5
- Passed: 5

## Conclusion

This practical exercise demonstrated why AI testing requires evaluating response quality and correctness rather than checking only whether a system produces an output.
